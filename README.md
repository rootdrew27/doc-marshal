# doc-marshal

Documentation **enforcement** for the AI age.

People and coding agents now write a repository's docs side by side, and both need them to hold a
shape. doc-marshal enforces one. Every note in the docs tree has a type, and the type decides what
the note must carry: its frontmatter, its sections, its folder and its filename. `doc-marshal check`
enforces it as an agent writes, at every commit, and on every pull request.

The frontmatter ties each note to the code it describes with its **anchor**. When that code
changes, `doc-marshal drifted` lists the notes that may no longer be true.

* Requires Python 3.11 or later, no runtime dependencies, and a git repository. 

* Supported: Claude Code on
macOS and Linux. The CLI, pre-commit and CI run anywhere Python does.

## Install

From the repository root:

```bash
uv add --dev doc-marshal==0.6.1                          # into the project's .venv, where the plugin's hooks look
uv run doc-marshal init --claude-code --pre-commit --ci  # marks docs/ as the docs tree and wires the integrations
uv run doc-marshal check --all                           # the tree validates from its first minute
uv run doc-marshal doctor                                # every route to the engine names the same version
```

Drop `--claude-code` to write a vendor-neutral `AGENTS.md` instead of `CLAUDE.md` and the plugin.
Not a Python project: `uv tool install doc-marshal==0.6.1`. For pip, Poetry and upgrading, see
[docs/setup.md](https://github.com/rootdrew27/doc-marshal/blob/main/docs/setup.md).

## Commands

```bash
doc-marshal new reference docs/ingest.md --summary "..." --code-ref src/ingest/sync_worker.py
doc-marshal check --all     # validate every note against the policies
doc-marshal drifted         # the notes anchored to code this branch touched
doc-marshal index           # every note with its type and summary
doc-marshal info            # the types; `info <type>`, `--policies`, `--marshalling` for more
doc-marshal doctor          # report the version every jurisdiction names
doc-marshal upgrade X.Y.Z   # install a version and move every pin to it
```

Every verb and flag: [docs/cli.md](https://github.com/rootdrew27/doc-marshal/blob/main/docs/cli.md).

## The standard profile

`init` writes these types into the docs tree's config, where you can edit, disable or add to them.

<!-- generated by scripts/render_doctrine.py from the profile -- do not edit -->
| Type | Serves | Voice | Mutability | Anchor minimum |
| --- | --- | --- | --- | --- |
| `reference` | someone looking up a fact -- decided by this repo, or observed from outside it | flat, enumerative, cites its source | mutable -- rewritten in place as the code or the world changes | any of `code_refs`, `source` |
| `runbook` | someone running a procedure | imperative, literal, copy-pasteable | mutable -- rewritten in place | `code_refs` |
| `decision` | someone about to reopen a settled choice | terse, one decision | append-only -- never edited after acceptance | none |
| `spec` | someone reading, building or validating a feature's behaviour as a whole | declarative, whole-feature, links to the references that justify it | mutable at every status -- in-progress whenever the doc leads the code | `code_refs` once `done` |
| `plan` | someone carrying out one piece of work to completion | ordered, imperative, each step checkable | mutable -- rewritten as the work moves, deleted once done | none |
| `convention` | someone about to write code or docs that must follow it | normative, one convention, states its scope | mutable -- rewritten in place as the convention changes | any of `code_refs`, `source` |
| `nomenclature` | someone choosing what to call a thing | flat, definitional, opinionated | mutable -- rewritten as the domain sharpens | none |

Each type in full: `doc-marshal info <type>` or
[rendered/doc-types.md](https://github.com/rootdrew27/doc-marshal/blob/main/rendered/doc-types.md).
Every policy: [rendered/policies.md](https://github.com/rootdrew27/doc-marshal/blob/main/rendered/policies.md).

## Integrations

`init --pre-commit --ci` writes both of these. For a repository that already has the files, add
them by hand.

Pre-commit, in `.pre-commit-config.yaml`:

<!-- generated: pre-commit -->
```yaml
- repo: https://github.com/rootdrew27/doc-marshal
  rev: v0.6.1
  hooks:
    - id: doc-marshal-check
```

CI, on every pull request. Keep `fetch-depth: 0`, because `drifted` reads a git diff:

<!-- generated: ci -->
```yaml
- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- uses: astral-sh/setup-uv@v6
- run: uvx doc-marshal==0.6.* check --all --format github
- run: uvx doc-marshal==0.6.* drifted --range "${{ github.event.pull_request.base.sha }}..HEAD" --format github
```

The Claude Code plugin in `plugin/` checks each note as it is written and briefs every session on
the docs tree. See [docs/integrations.md](https://github.com/rootdrew27/doc-marshal/blob/main/docs/integrations.md).
