# Rules for a doc-marshal docs tree

The **docs root** is the directory holding the `{{marker_name}}` marker; one repository has one.
Paths below are relative to it unless stated otherwise.

---

## 1. Notes

A note is a `.md` file under the docs root. Notes are what the rules govern. Everything else under
the docs root is one of these, never validated and never indexed:

| Path | What it is |
| --- | --- |
| `{{assets_dirname}}/**` | attachments (§2) |
| `{{index_name}}` at the docs root | the generated index (§5) |
| {{memory_names}}, anywhere | instructions to an agent: no frontmatter, no type, outside these rules |
| `{{marker_name}}` | the marker naming this directory the docs root |
| {{excluded_dirs}} | tooling and metadata |
| any file with another suffix | not markdown |

Errors by name, in any spelling of case, anywhere under the docs root:

- `README.md` -- the generated index is the only front door.
- Any spelling of `{{index_name}}` other than `{{index_name}}` itself at the docs root: the one
  index is generated, there.
- A markdown suffix other than `.md` -- `.markdown`, `.MD` -- rename it.

## 2. Attachments

`{{assets_dirname}}/` at the docs root holds non-markdown files: PDFs, images, exports. It is
optional, and nothing inside it is checked, at any depth. Two errors, reported by a sweep
(`check --all`):

- A markdown file under `{{assets_dirname}}/`.
- An `{{assets_dirname}}/` directory anywhere but the docs root.

Anchors (§4) name attachments by path, so renaming one breaks every anchor to it, and `check`
reports each.

## 3. Naming and placement

- A note's filename and every folder above it, up to the docs root, is kebab-case:
  `^[a-z0-9]+(-[a-z0-9]+)*$`. ASCII only; a name may start with a digit; a dotfile fails unless
  §1 exempts it.
- Exempt: everything under `{{assets_dirname}}/`, the non-notes of §1, and a filename a type
  claims -- today {{fixed_names}}. A claimed filename binds both ways: that type must use it, and
  no other type may.
- A type that names a folder lives in it; a numbered type is named `NNNN-kebab-slug.md` (§7).

## 4. Frontmatter

Every note opens with a YAML block of scalars and dash-item lists. Three fields are required on
every type:

| Field | Rule |
| --- | --- |
| `type` | one of the enabled types -- `doc-marshal info` lists them |
| `updated` | a real date, `YYYY-MM-DD`, not in the future; a note this change edited carries a date no earlier than the day the change began -- today for the working tree, the earliest commit of a `--range` |
| `summary` | one line, at most {{summary_max}} characters |

No other key is allowed beyond the ones the type declares: the three above, every declared anchor
field, `status` where the type has statuses, and the supersession pair where the type declares
one. An unknown key is an error. Where a type has statuses, `status` is required and must be one
of them; the supersession rules are `doc-marshal info <type>`.

### Anchors

An anchor names what outside the note would falsify it. Each field is validated whenever present,
on any type; a type's minimum is the fields of which a note must carry at least one, from the
status the type names, if it names one.

{{anchor_table}}

- A path is written from the repository root, never absolute, with no `.` or `..` segment, and
  spelled exactly as the filesystem has it. It names a file or directory strictly inside the
  repository: `.` is not an anchor.
- A path must be tracked by git, whichever field holds it. Untracked and ignored files are
  errors, and so is a gitignored `{{assets_dirname}}/`. Outside a git repository every path
  anchor is an error.
- A `docs-path` resolves inside the docs root; a `repo-path` resolves anywhere in the repository.
- A `url` is `http://` or `https://`.
- **Warning:** a note anchored only from a status onward, in that status, edited by a change that
  touched none of its `repo-path` anchors -- today {{spine}}. The doc may now lead the code.

`doc-marshal affected` matches every path field against a diff.

```yaml
---
type: reference
updated: 2026-08-07
summary: Modbus register map for the pump controller, as specified and as observed.
source:
  - docs/assets/pump-controller/protocol-spec-rev-c.pdf
code_refs:
  - src/pumps/modbus_client.py
---
```

## 5. The index

`{{index_name}}` at the docs root is generated by `doc-marshal index` from every note's `type`
and `summary`, and is never written by hand. Regeneration is whole-tree: one note with a missing
`type` or `summary` blocks it, and the builder names that note. The pre-commit hook regenerates
it; CI reports a stale one as a warning.

## 6. Links

- A link to a local file is a relative markdown link, `[text](../a/b.md)`, images included.
  Wikilinks and absolute paths are errors.
- The target must exist, inside the repository. A heading anchor, `#slug`, must match the
  lower-case slug GitHub makes of a heading in the target, exactly.
- A destination in angle brackets, `[x](<a name.md>)`, is read. A link with a URL scheme, and a
  link inside a code span or a fenced block, is not checked.

## 7. Numbered notes

A numbered type lives in its folder as `NNNN-kebab-slug.md`, zero-padded to four, and its H1
starts with the same number and ` -- `. Numbers are unique within the folder. `doc-marshal new
<type> <slug>` derives the number, the path and the title prefix.

## 8. Structure

- Exactly one H1, and it is the first heading. Headings inside fenced blocks do not count.
- A type's required sections, `doc-marshal info <type>`, are each present once, in that
  relative order, each with content once HTML comments are stripped. Other sections may appear
  anywhere.
- A section a type must have empty from a status onward, in that status, has no content.
- Heading levels are not otherwise checked.

## 9. Nomenclature

A `nomenclature` note's body is parsed, so its shape is fixed; `doc-marshal info nomenclature`
gives the sections, columns and caps.

- The docs root carries one. At most one per directory; a nested one adds terms and never
  redefines a term an ancestor defines, compared in any case.
- One row per term, compared in any case. A word under `Avoid` that is also a term is an error.
  A row with an empty term is an error. A literal pipe in a cell is `\|`.
- Three caps, each an error: the table's rows, the characters of the body outside the table, and
  a definition's length.
- **Warning:** a note using a word an `Avoid` column rules out. The scan reads the body and the
  frontmatter `summary`, as whole words in any case, and follows a wrapped alias within a
  paragraph. It skips code spans, fenced blocks, HTML comments, append-only types and
  nomenclature notes themselves.

## 10. Where the rules run

| When | What runs | Effect |
| --- | --- | --- |
| every write to a note | `check <that file>`, via the Claude Code plugin's PostToolUse hook | reports into the session; never blocks |
| every `git commit` | `check` on staged notes, then `index`, via the pre-commit framework | errors block; a regenerated index fails the hook for re-adding |
| every pull request | `check --all --format github`, `index --check` | errors fail the build, each on the file it names; a stale index warns |
| every pull request | `affected --format github` | annotates anchored notes; never fails |

The change a run is scoped to is the working tree against `HEAD` plus untracked files, or
`--range A..B`: two commits, `A` an ancestor of `B`, or the command exits 2. A `git mv` with no
content change is not an edit; a plain `mv` is. There is no inline suppression and no severity
configuration; what is configurable lives in `{{marker_name}}`.

Git is required: the tracked-anchor rule, the freshness window and `affected` are questions to
git. Claude Code on macOS and Linux is the supported platform; the CLI, pre-commit and CI run
anywhere Python does.
